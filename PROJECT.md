# DocScanner — Project Guide

**Repository:** https://github.com/faria2177/DS-Fult  
**App:** DocScanner (DC / DS)  
**Current documented baseline:** `0.5.10+24` (8 November 2026)  
**Primary target:** Android; **technology:** Flutter/Dart with an Android-native document detector.

> **বাংলা সারাংশ:** DocScanner একটি লোকাল-ফার্স্ট Android ডকুমেন্ট স্ক্যানার। ক্যামেরা থেকে স্ক্যান, চার কোণা শনাক্তকরণ, Crop/Filter, ID Card-এর দুই পাশ এক A4 পেজে সংরক্ষণ, OCR, Files এবং PDF/Office export এর কাজ এখানে করা হচ্ছে। কোনো ক্লাউড অ্যাকাউন্ট বা Ask AI প্রয়োজন নেই।

## Mission

Build a fast, stable, offline-first document scanner with a familiar, polished document-scanning experience, including reliable page-border detection and functional editing/export tools. Reference videos and screenshots guide our **independently implemented** Flutter UI; they are not permission to copy proprietary code, art, or services.

## Product principles

1. **Local by default.** Scanned documents, the document index and edits stay on the device. System sharing/printing occurs only when the user invokes it.
2. **Preserve data.** Keep originals when practical; do not silently discard images because a crop detector is uncertain.
3. **Manual control.** Manual shutter, four-corner adjustment, rotation and a review step remain available. Automatic capture is disabled by default.
4. **Working controls.** Do not add an attractive but inert button or claim an experimental effect is AI-quality restoration.
5. **Consistent navigation.** Android system bars, Back, long-press selection and camera transitions must work correctly.
6. **Reference fidelity with honesty.** Match the demonstrated layout and interaction where practical; hardware differences and proprietary algorithms prevent guaranteed pixel-perfect or processing-identical output.

## Non-goals and boundaries

- No proprietary CamScanner code/assets, cloud sync, cloud AI or **Ask AI** menu.
- No claim that app-level PIN locking encrypts the underlying image/PDF bytes.
- No claim that OCR reconstructs every table, layout, font or imported native PDF perfectly.
- No unsupported claim of full Android/iOS/desktop parity. The active release/test workflow is Android.
- Tools explicitly removed from the Tools grid remain hidden unless the user requests them again; do not confuse internal helper code with a visible feature.

## Build from a fresh checkout

Prerequisites: **Flutter 3.47.4**, Dart 3.13.x, Java 17, Android SDK and an Android device/emulator.

```bash
git clone https://github.com/faria2177/DS-Fult.git
cd DS-Fult
bash tool/setup_android.sh
bash tool/download_ocr_models.sh
flutter pub get
bash tool/patch_tesseract_gradle.sh
flutter analyze
flutter test
flutter run
```

The `android/` host template is generated by `tool/setup_android.sh`; it is not a conventional checked-in Flutter Android host. The Bengali OCR model is bundled **at build time** through `tool/download_ocr_models.sh`. The Tesseract Gradle patch is a build-time compatibility step.

## Release and verification

`.github/workflows/android-apk.yml` runs on `main`, pull requests, and manual dispatch:

1. Flutter/Java setup and Android-host generation.
2. Bengali OCR asset preparation and dependencies.
3. Native document-detector unit tests.
4. `flutter analyze` and `flutter test`.
5. `flutter build apk --release --split-per-abi` and `DocScanner-Android-APKs` artifact upload.

The `0.5.10+24` baseline passed these CI steps on [run #42440988584](https://github.com/faria2177/DS-Fult/actions/runs/42440988584). CI success **does not** replace camera/UI testing on physical devices. For a 64-bit HONOR Android phone, install the `arm64-v8a` release APK from the artifact ZIP.

- Report exactly which files changed, which checks ran, and which parts remain unverified on hardware.
